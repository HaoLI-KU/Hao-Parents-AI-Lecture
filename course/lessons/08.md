# 第 8 节｜写项目指令、阶段路线与内容规则

## 爸爸｜让下一次 Harness 会话接着做

第 7 节已把选中的 Overleaf 中文模板与第一份 Word 分开放好。今天只写眼前会用到的三份 Markdown：项目入口 `AGENTS.md`、阶段路线 `ROADMAP.md`、内容保持规则 `standards/word-conversion.md`。Markdown 可以用普通文本编辑器打开，`#` 表示标题，`-` 表示一条清单。

### 1. 先分清六种记录

| 名称 | 回答什么问题 | 本节怎样处理 |
|---|---|---|
| `AGENTS.md` | Harness 在这个项目先读什么、可改哪里、怎样汇报？ | 放在 `Technical-Publishing/` 根目录，写长期边界和文件索引 |
| `ROADMAP.md` | 现在在哪一阶段，下一小步是什么？ | 写已验证的模板、首段转换、后续批量转换的顺序 |
| Standard | 已确认的内容或排版要求是什么？ | 先写 `standards/word-conversion.md` 中少量确定规则 |
| Development | 曾遇到什么重要问题，为什么采用某种解决办法？ | 等第 9 节有真实决定再建，避免预填假经验 |
| Skill | 下次同类任务按什么步骤重复？ | 第 9 节验证完一次转换后再写 |
| Tests | 怎样检查改动没有破坏已能工作的部分？ | 第 9 节从实际编译和核对中写出 |

一句话记：入口管边界，路线管阶段，Standard 管要求，Skill 管步骤，Tests 管验证，Development 管决定的原因。`CLAUDE.md` 也是部分工具和 Harness 配置可读取的项目指令候选文件；本项目先用一份 `AGENTS.md`，不复制一套相同内容。以爸爸本机新会话读到的文件为准。[Harness 项目指令说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md)

### 2. 让 Harness 起草，爸爸确认后写入

先打开第 4 节保存在本机的一页项目说明。让 Harness 读取它和第 7 节的目录，**只在会话里提出草稿**，不要立即写入文件。

```text
当前工作区是 Technical-Publishing/。请先读取我本机第 4 节留下的项目说明，再只读查看 template/ 和 projects/book-001/ 的目录。找不到项目说明时先问我位置，不要猜测内容。
请在会话中起草根目录 AGENTS.md、ROADMAP.md 和 standards/word-conversion.md，暂时不要创建或修改文件。
AGENTS.md 写清先读哪些现有文件、只修改 template/technical-book/ 与 projects/book-001/latex/ 等工作副本、原件和留存副本不得覆盖，以及每轮先报告计划和结束时报告核对结果。
ROADMAP.md 区分当前已验证的 Overleaf 中文模板、下一步的 Word 小段转换、以后分批转换与复用。Standard 只写已经确定的内容保持规则；未确定的排版细节标待定。
请逐份列出拟写内容和依据，等我对照项目说明与 Finder 确认。
```

爸爸逐条核对草稿：目录名是否真存在，Word 的技术内容是否被当作输入，已经验证的通用模板和项目实例的范围是否写对，是否把未决定的字体或图表样式误写成规则。确认后，在 Harness 中说「按刚确认的三份草稿写入对应路径，只创建需要的 `standards/` 目录，不动其他文件」；再从 Finder 打开三份文件核对。若 Harness 无法写入，爸爸也可以把确认后的文字粘贴到本机文本编辑器保存。

三份文件可以从下面的**公开示例**起步，实际内容应按爸爸本机项目说明和目录修改。

```markdown
# AGENTS.md｜项目入口
先读 ROADMAP.md；转换前再读 standards/word-conversion.md。
原件与 template/original-overleaf/、projects/book-001/original/ 只用于读取和核对，不覆盖。
本轮可从 template/technical-book/ 复制模板实例到 projects/book-001/latex/；通用模板不放私人正文。
动手前列出将读、将改的文件及检查办法；完成后报告结果和未解决问题。
```

```markdown
# ROADMAP.md｜阶段路线
目标：忠实转换 Word，形成可长期复用的中文 LaTeX 模板和流程。
当前：第 6 节选定的 Overleaf 模板已完成中文、多章节与功能检查。
下一步：转换 book-001 的一小段，编译并逐项核对。
以后：分批转换全篇，验证图表与引用，再复用到下一份文档。
```

```markdown
# standards/word-conversion.md｜已确认规则
- 不覆盖 Word 与模板原件，也不改项目内的留存副本。
- 转换时保留正文、数字、单位、公式、表格数据和技术结论。
- 表格可以重新排版；图可在人工确认后重绘，但不能改变数据或技术连接关系。
- 原稿编号与 LaTeX 引用建立可核对的对应关系；语言润色与格式转换分开，改字句先征求爸爸确认。
```

这三份文件各管一件事：`AGENTS.md` 只给工作边界和索引，不复制整份 Standard；`ROADMAP.md` 只记阶段；Standard 记可以重复使用的要求。第 9 节若发现规则需要调整，先核对真实结果，再改文件。

### 3. 开新会话验证它读到了什么

关闭当前会话，从项目根目录打开 Harness 新会话，发送只读提示词：

```text
请先读当前项目根目录的 AGENTS.md、它指向的 ROADMAP.md，以及 standards/word-conversion.md。暂时不要修改文件或开始转换。
请用自己的话列出当前阶段、下一小步、可以修改的工作副本、不能覆盖的原件，并给出你实际读取的相对路径。找不到文件就报告，不要按记忆补写。
我会打开这三份 Markdown 和 Finder 目录逐项对照，再决定下一步。
```

爸爸逐项对照三个文件和 Finder。若它没有读到，先确认 Harness 工作区是不是 `Technical-Publishing/`，再明确提供文件路径重试，并记下本机的加载情况。完成时，新会话能说对项目阶段和原件边界，爸爸能指出以后该把步骤、检查和重要决定分别放在哪里。

## 妈妈｜用 DeepSeek Harness 做一个「我的养花笔记」

这周先用 DeepSeek Harness 做一张网页，里面有两条示例养花记录；随后只改一条记录，看看网页怎样跟着更新。

### 第 0 步：装好 DeepSeek Harness

1. 打开 [DeepSeek Harness 官方发布页](https://github.com/DeepSeek-ai/deepseek-harness/releases)，在所选版本的 Assets 里找适用于 macOS Apple Silicon 的桌面安装文件，安装到「应用程序」并打开。若页面只有源码，先核对家里已安装的桌面版和更新入口。
2. 准备自己的 DeepSeek 开放平台账户。打开 [DeepSeek 开放平台](https://platform.deepseek.com/)，注册或登录妈妈自己的账户，按页面完成验证；还没有余额时按页面提示小额充值。
3. 在 Harness 的模型设置里配置提供方和自己的 API Key。先停止屏幕共享，再由妈妈本人粘贴密钥；密钥不写进聊天、截图或课程仓库，也不要用爸爸的密钥。
4. 新建一个对话，输入「请只回复：连接成功。」看到回复再继续。若提示认证失败，核对密钥和提供方；若提示余额不足，回开放平台查看余额。
5. 找不到安装文件或模型设置时，先记下显示的名称、版本和按钮，不要跳过。爸爸第 2 节的安装清单可以对照，但账户和密钥各自用自己的。

### 第 1 步：把想要的网页说清楚

在「文稿」新建空文件夹 `plant-notes`，在 DeepSeek Harness 里选它作为当前项目。可以直接口述下面的提示词：

```text
请在当前文件夹做一个简体中文单页网站，标题叫「我的养花笔记」。只创建三个文件：`index.html`、`plants.json`、`app.js`。HTML 放标题和卡片区域，样式简单清楚，写在 HTML 里。JSON 放两条示例记录：绿萝和薄荷，每条有名称、位置和观察笔记。JavaScript 用相对路径读取 JSON，把两条记录显示成卡片。用本机已有的工具启动仅本机可访问的预览，告诉我在浏览器打开哪个地址。如果预览需要额外安装软件，先告诉我。请只在这个练习目录工作，做到本地预览为止。
```

### 第 2 步：在 Finder 和浏览器里检查

| 文件 | 它负责什么 |
|---|---|
| `index.html` | 网页的结构，例如标题和卡片区域 |
| `plants.json` | 植物记录，像一张用固定字段写成的小表 |
| `app.js` | 读入植物记录，再把它们显示到网页上 |

1. 在 Finder 找到三个文件。请 Harness 给出本地预览地址，用浏览器打开，确认出现绿萝和薄荷两张卡片。网页通过本地预览读取 JSON，直接双击 HTML 时可能读不到数据。
2. 再说一句：「只改 `plants.json`，把薄荷的观察笔记改成『今天长出了两片新叶』。」刷新浏览器，检查只有薄荷的那条文字变了。
3. 看着 Finder 里的文件，说出下次要加一种植物应该改哪一个文件。以后想加照片或视频，可以从现有的卡片继续扩展。

本节做到本机可以预览、修改一条记录并看到更新。
