# 第 12 节｜在 Harness 里浏览图纸并标注

状态：后续课 · 待现场验证

<a id="dad"></a>

## 爸爸｜把图纸打开，点一个热点，写一条批注

第 10、11 节处理的是文字清单。真正推敲图纸时，你还是想看着图说话：这里少一个阀、那条线为什么绕、这个位号和上一张图对不上。这一节把 DXF 变成一页可以缩放、按图层显示、点选和批注的审图页，再把它接回 Harness 的会话。

这一节先标「后续课」：脚本本身已经在虚构示例上跑通，但 Harness 预览里的批注浮层需要在你本机确认一次；确认前不要把它当成已经稳定的流程。

### 1. 生成审图页

用同一个工具把一张 DXF 生成 HTML：

```sh
.venv-cad/bin/python tools/make_review_sheet.py dxf/DEMO-PFD-001.dxf \
  -o review/DEMO-PFD-001.html --title "糖浆配制工艺流程图"
```

- 几何用矢量 SVG 逐图层渲染，放大不糊；中文文字单独叠加，所以不依赖 AutoCAD 的 SHX 字体。
- 每个设备、仪表和标题栏文字都有一个稳定的热点编号，热点带 `handle`，能对回 DXF 实体。
- 默认黑线白底、按图层分开；想保留图层颜色时加 `--colors`。
- 单文件、无外部依赖，可以离线打开。

想先看看成品，可以打开虚构示例的[审图页](../../assets/lessons/10/examples/cad/sample-review.html)。

### 2. 打开它的两种方式

1. **在 Harness 里看。** 从右侧 Files 面板找到 `review/<图号>.html` 打开预览。预览宽度有限时用页面自带的缩放和拖动；需要更大画面就在浏览器里打开同一文件。
2. **在浏览器里看。** 双击 HTML 文件，或在 Finder 里右键「打开方式 → Safari」。这一页不联网也能用。

两种方式看到的是同一个文件，批注也存在同一个地方。

### 3. 页面上能做什么

| 操作 | 怎么做 | 用途 |
|---|---|---|
| 放大 / 缩小 / 适应窗口 | 左侧按钮；按住 `⌘` 滚动也可以 | 看局部细节 |
| 平移 | 在空白处按住拖动 | 看图纸另一端 |
| 按图层显示 | 左侧图层勾选框 | 只看设备、只看仪表、只看管线 |
| 看实体信息 | 点图纸上的编号热点 | 位号、名称、图层、块名、handle |
| 写批注 | 点热点 → 在文本框写 → 保存批注 | 把你的疑问挂在具体实体上 |
| 导出批注 | 导出批注 JSON | 交给 Harness 读取 |
| 复制批注 | 复制成 Markdown 列表 | 贴进会话 |

批注存在本机浏览器里，导出文件默认叫 `<图号>-notes.json`。把它放进 `review/`。

注意：Harness 的 HTML 预览是一个受限的沙箱页面，页面自带的批注可能存不住，下载也可能被拦。在预览里优先用「点选批注」浮层；要长期保存页面自带的批注，就在浏览器里打开同一份 HTML，或在导出后把文件放进 `review/`。

### 4. 在 Harness 里直接用批注浮层

第 2 节装过 HTML 批注插件（Installed plugins 里显示为 **HTML Annotations** 或 `dsh-annotate-sync`）。它会在 HTML 预览上自动出现「点选批注」浮层。

1. 在 Files 面板打开 `review/<图号>.html`，确认预览区出现批注入口。**这一步以你本机的实际显示为准**：有的版本自动出现，有的需要点一下「点选批注」。
2. 点图纸上的编号热点，写一条批注，例如「这台泵出口没有止回阀？和上一版图纸不一致」。
3. 退出点选，点「发送给 Agent」，整批批注进入当前会话。
4. 如果浮层不出现，不要卡在这一步：在浏览器里打开同一份 HTML，用页面自己的「导出批注 JSON」，把文件放进 `review/`，第 5 步同样可以继续。

批注记录里有页面选择器和 `hs-<handle>`，所以 Agent 能直接对回实体，而不是只看到一句脱离图纸的评论。

### 5. 让 Harness 按 handle 回应批注

把清单和批注放在一起交给它，并要求只提讨论点。

```text
当前工作区是 CAD-Review/。请只读 inventory/<图号>.json、review/<图号>-notes.json 和 review/<图号>.html，不要修改 original/ 和 dxf/ 里的任何图纸。
请按 handle 把每条批注对回实体，逐条回答：
1. 这条批注涉及哪个位号、哪条原文、在图纸的哪个位置；
2. 从清单能确认什么；
3. 从清单不能确认什么（需要看原图或做工艺判断的部分）；
4. 值得进一步讨论的两三个问题，按重要性排序。
只提讨论点，不要给工艺结论，不要改图，也不要替我决定哪一版是对的。
```

如果批注是浮层直接发过来的，它可能带着 `selector` 或「第 N 号热点」这样的信息。让 Agent 说明它把哪条批注对到了哪个 handle；对不上的，贴回本文档再问一次。

### 6. 把讨论结果留下来

讨论结束后，在 `review/<图号>-讨论.md` 里记录：批注原文、对应 handle 或位号、从清单能确认的事实、仍需原图判断的问题、你的结论或「待定」。

这份记录和 `notes/` 里的阅读记录是两件事：`notes/` 记这张图读得对不对，`review/` 记这张图讨论出了什么。不要混写。

### 7. 关于「原生图纸面板」

现在这条路是：脚本生成审图页 → Harness 预览或浏览器打开 → 批注回到会话。好处是零安装、可离线、换电脑也能用。

如果以后你希望 Harness 里有一个固定的「图纸」面板——左边列图纸、右边看图、不经过 Files 面板——那是一个单独的插件项目，需要另外设计和验证，不在这一节承诺。

### 检查清单

- [ ] 至少一张图生成了审图页 HTML，能在浏览器打开。
- [ ] 缩放、平移、图层勾选都试过，图纸细节看得清。
- [ ] 点热点能看到位号、图层和 handle。
- [ ] 至少写了并保存一条批注，导出的 JSON 放进了 `review/`。
- [ ] 在 Harness 预览里确认过批注浮层是否出现（记录本机结果）。
- [ ] Agent 能把每条批注对回具体 handle，且没有编造工艺结论。
- [ ] `review/<图号>-讨论.md` 记下了事实、待确认项和你的判断。

完成这一节后，这套流程就可以按「归档 → 清单 → 核对 → 审图批注」重复使用了。
