第 2 讲已经完成 Harness、微信输入法和插件安装。这节在 **DeepSeek Harness** 中练习模型、推理强度和开放平台用量，再分别练习公开网页读取和本机 Calendar 只读。

### 1. 先认清模型与推理强度

1. 打开 DeepSeek Harness，新建一个空练习会话。
2. 打开模型选择器，确认提供方是 DeepSeek，并记下当前模型名。模型列表以本机实际显示为准；若能选择 `deepseek-flash` 和 `deepseek-v4-pro`，先用 Flash 做简单练习，需要更复杂推理时再比较 Pro。
3. 找到 Effort 或推理强度。Harness 的 DeepSeek 直连可能显示 `off`、`low`、`high`、`max`。先说出它控制的是「模型愿意投入多少推理」，不是文件权限，也不会自动开启联网搜索。
4. 复杂问题不一定总要最高档。简单整理先用低档；条件多、需要比较时再提高，并通过结果判断是否值得。

[DeepSeek Harness 模型配置说明](https://deepseek-harness.github.io/deepseek-harness/guide/providers.html) · [DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)

### 2. 用同一道题比较两个档位

在两个新会话里使用同一个模型和完全相同的问题，只改变推理强度。下面用虚构行程练习，比较时不要改动提示词中的条件。

```text
我要安排一次半天家庭出行。两位长辈不想走太多路，上午 9:30 从上海长宁区出发，12:30 前回家。
请先列出你还缺少的三个关键信息，再给一份暂定安排。
交通时间未经核实的地方请标「待核实」。最后列出我需要亲自核对的两件事。
```

1. 第一次选择 `low`；记录发送时间、回复所用时间、追问是否有针对性，以及有没有忽略条件。
2. 第二次选择 `high` 或 `max`；其余内容不变，再记录同样四项。
3. 把两次结果并排看。重点不是哪一份更长，而是哪一份更准确地使用了条件、清楚区分了待核实信息。

做自己的出行安排时，可以替换人数、出发地和时间。比较两个推理档位时，两次仍须使用完全相同的文字。

### 3. 回开放平台找这两次用量

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/)的用量或账单页面，选当天和自己用于 Harness 的 API Key。
2. 对照刚才记录的时间，观察平台能否区分两次请求。页面显示哪些字段就读哪些字段，例如输入 token、输出 token、思考 token、缓存或费用；不要用屏幕字数猜 token。
3. 记录两次请求能确认的模型、档位、耗时和用量。若明细延迟出现，先记下时间，稍后刷新，不重复发送许多测试。
4. 说出结论：「高档是否更慢？是否用了更多 token？这道题的答案是否真的更好？」一次练习只说明本次任务，不代表所有问题。

[DeepSeek Token 用量说明](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/) · [DeepSeek 定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

### 4. 读一条公开网页

从机票、商品比价或上海便民信息中挑一个需求，用微信输入法口述进 Harness。先用公开网页练浏览器读取。可以按自己的兴趣改成另一项公开政策，仍要求它给出原文链接和待核实之处。[上海市人民政府](https://www.shanghai.gov.cn/)

```text
请用当前可用的网页读取工具，在上海市人民政府网站找一条与长者服务有关的公开办事指南。
给出标题、发布单位、发布日期、正文链接和一条适用条件，并指出支持这条条件的正文位置。
先报告你实际打开了哪些页面、读到了哪些正文。只看到搜索摘要或读不到正文时请说明，不要补猜。
我会打开原链接，核对域名、日期和适用条件。
```

打开同一链接，核对域名、日期与适用条件，并查看 Harness 是否确实读取了公开页面。若工具打不开正文，就自己打开官方页面，把可公开的段落复制进会话，让 Harness 只根据这段文字整理；不要用登录后的私密页面冒充公开读取。

### 5. 只读本机日历

Harness 没有专门的“日历按钮”。当前实际路径是：由 Harness 调用本机 macOS 的 Calendar 自动化（AppleScript），读取 Calendar.app 里的数据。**不是登录 iCloud 网页，也不是用普通网页读取。**

这条路径需要 macOS 自动化权限。只做只读查询，不创建、不修改、不删除日程；只查指定标题的测试日程，不导出全部日历。

1. 先在日历中新建一条标题为「家庭出行测试」的练习日程，设置当天的开始、结束时间，自己记下来。
2. 先做一次只读权限检查：让 Harness 只读取日历列表，不读取事件内容。若失败，打开「系统设置 → 隐私与安全性 → 自动化」，确认实际发起调用的 App（DeepSeek Harness 或运行命令的终端，以本机权限列表为准）可以控制“日历”，再试一次。
3. 再发送下面的只读提示词：

```text
请只通过本机 macOS Calendar 自动化读取标题为「家庭出行测试」的事件，
不要打开 iCloud 网页，不要创建、修改或删除日程。
报告它的日期、开始和结束时间、时区，并按时间顺序整理成一行行程。
如果找不到、遇到多条同名日程或没有自动化权限，请说明实际查到什么，不要假装读到了。
```

4. 对照日历原记录核对时间和时区。若权限仍不可用，就打开日历，把这条测试日程的文字复制进会话，再发送：

```text
下面是我从日历复制的测试日程文字，请只根据这段文字整理，不要声称读取了日历。
```

5. 查看 Harness 是否明确说明“读取的是本机 Calendar 自动化”，而不是含糊地说“读了你的日历”。

### 收尾


完成时，你应能在 Harness 里指出模型名和 Effort，从开放平台找到至少一条对应的用量记录，并说明网页是公开读取、日历是本机自动化读取或由本人复制。

### 妈妈清单

这一讲两人同一份内容，用同一道虚构题比较推理强度。

1. 在 Harness 里找到模型名和 Effort。
2. 用这一讲的虚构行程题，分别用 low 和 high/max 各做一次。
3. 回 DeepSeek 开放平台核对两次请求的用量。
4. 用微信输入法口述一条提示词，按这一讲读一条公开网页；日历只读本机测试日程，不创建或修改，也不使用 iCloud 网页。
