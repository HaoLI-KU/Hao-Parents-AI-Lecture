单张图读准之后，真正花时间的是「一批图放在一起看」。这一讲不追求一次处理几百张，先把 3–5 张关联图纸的台账和疑点清单跑通。

### 1. 选一批有关联的图

1. 从同一套装置或同一阶段里选 3–5 张，例如总流程、反应、分离各一张。
2. 每张都按第一讲另存成 DXF，文件名用图号，放进 `dxf/`。
3. 在 `notes/` 里各写一行：这张图是什么、和图里哪几张相关、有没有未绑定参照。

### 2. 批量生成台账

```sh
.venv-cad/bin/python toolkit/cad.py inventory dxf/ -o inventory
```

每张图生成一份 `.md` 和 `.json`，另外汇总 `inventory/ledger.csv`。先看台账：

| 列 | 先看什么 |
|---|---|
| `file` | 是否都用图号 |
| `dxf_version` | 是否统一到 AC1032（R2018） |
| `entities` / `texts` | 明显偏少可能是参照没绑定 |
| `equipment` / `instruments` | 与印象差太多时先核对 |
| `tags` | 用于发现漏提取 |
| `warnings` | 不为 0 的图先处理 |

台账不是结论，只是「这批图能不能读、读到了多少」的体检表。

### 3. 让 Harness 只列疑点

```text
当前工作区是 CAD-Review/。请只读 inventory/ledger.csv 和这批图的清单（.md 与 .json），不要打开或修改 original/、dxf/ 里的图纸。
请做一次跨图核对，但不要下结论。只列需要我人工确认的项目，分四类：
1. 同一位号在不同图纸里名称、参数或位置不一致；
2. 设备或仪表位号重复、跳号、或只出现在一张图里；
3. 图层命名、图框版本、图号格式不一致；
4. 清单里读不到或可能缺内容的地方（外部参照、代理对象、编码问题）。
每条写清：疑点、证据（文件 + handle + 原文）、为什么值得核对、建议我在原图里看哪里。
没有把握的写「待确认」，不要编造位号，也不要替我判断工艺是否合理。
最后列出你认为我应该先核对的三条，并说明理由。
```

### 4. 逐条判定

在 `notes/cross-check-<日期>.md` 里逐条判定：

| 判定 | 什么情况用 | 记录要写什么 |
|---|---|---|
| 成立 | 原图确实如此 | 图号、handle、原图位置、你的判断 |
| 不成立 | 清单提取或 AI 理解有误 | 错在哪：文字、块、图层还是推断 |
| 需原件确认 | 本机副本看不清或版本不对 | 缺什么、去找哪份原件 |

没核对到的写「待核对」，不填「通过」。

### 5. 把规则留下来

跑完两三批图后，只写已经确认的规则到 `standards/cad-review.md`：

```markdown
# standards/cad-review.md｜图纸核对规则
- 位号格式：设备用「字母-三位数字」，仪表用「两位功能字母 + 编号」；以本装置现有图纸为准。
- 图号与文件名一致；另存 DXF 统一用 AutoCAD 2018 DXF。
- 先绑定外部参照再另存；有未绑定参照的图不进入跨图核对。
- 文字编码：R2004 及以前用 $DWGCODEPAGE，出现乱码先用 ODA 重出 ACAD2018。
- inventory warnings 不为 0 的图先处理，不进入下一步。
- AI 只能提出疑点；每条结论必须能指回「文件 + handle + 原文」。
```

不确定的标「待定」，不要写成制度。

### 检查清单

- [ ] 这一批 3–5 张图都按图号命名并另存为 DXF。
- [ ] `ledger.csv` 已生成，每张图一行。
- [ ] `warnings` 不为 0 的图已处理或已记录原因。
- [ ] 跨图结果只包含「疑点 + 证据 + 建议核对位置」。
- [ ] 每条疑点都有成立/不成立/需原件确认的判定。
- [ ] `standards/cad-review.md` 只写已确认规则。
