让下次更新养花笔记更容易

给养花小站写维护规则

本节步骤

01验证规则

参考爸爸第 8 节的项目入口和规则练习。沿用「先看实际项目、分开写规则、再验证」的办法。打开自己第 8 节做的养花小站，先看现有的三个文件和你的第 9 节 GitHub 共同练习用过的仓库。

Markdown 文件 先写一条对养花网站有用的规则
AGENTS.md 让 DeepSeek Harness 先读下面列出的规则，改之前告诉我会动哪些文件。
guide/structure.md index.html 是页面入口，plants.json 是植物记录，app.js 负责显示。将来要用照片时再约定位置和文件名。
guide/style.md 新记录沿用现有卡片样式，标题和照片说明用容易读的短句。
guide/language.md 用简体中文记录自己的观察。把「我看到什么」和「我猜是什么原因」分开。
  1. 先请 Harness 只检查现有文件，给出四份 Markdown 的提案。请它用「增加一条植物记录」举例，说明应该读哪几份规则、改哪个文件、怎样检查。
  2. 看过后确认写入哪些文件。先写 AGENTS.md 和目录规则即可。视觉和语言约定有明确想法时再加，入口只引用已经存在的规则。
  3. 开一个新对话，试说：「按项目规则加一条虚构的吊兰记录。先告诉我你读到了哪些规则、准备改哪个文件。」核对它找到了 plants.json 后，再让它改。打开本地预览，看看是否多了一张卡片。

验证规则

  1. 关掉会话，重新从养花小站文件夹打开 Harness 新会话，再发上面那句话。看它是否先读 AGENTS.md 和 guide/ 里的规则，再指出只改 plants.json。
  2. 若它没读规则，先确认工作区是不是养花小站文件夹，再明确说「先读 AGENTS.md 和 guide/ 里的规则」。仍不读就记下它实际读了哪些文件。
  3. 改完后刷新本地预览，确认多了一张吊兰卡片，原来的绿萝和薄荷还在。
  4. 用一句话说出：下次加照片或改样式，应该先看哪份规则、再改哪个文件。

完成时，养花小站有 AGENTS.md 和至少一份 guide/ 规则，新会话能按规则改一条记录，预览能看到结果。没通过的项目记在本机，下次继续。
